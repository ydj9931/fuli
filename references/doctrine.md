# 富丽 FULI Doctrine v0.2

> Doctrine 是方法论，不是普适真理。

## 1. 富丽关心的不是效率，而是复利

单次节省时间不是最高目标。

更重要的是：

> 今天的工作是否能在未来继续产生价值。

## 2. 创作优先于吞吐量

不以完成最多任务为目标。

优先寻找能够沉淀为方法、Workflow、Skill、Capability、Work、Reputation、Better Questions 的活动。

## 3. 真实工作是传感器

真实工作提供真实限制、真实矛盾、真实用户、真实组织、真实失败和真实反馈。

这些可以成为长期创作的原料。

## 4. 组织事实留在边界之内

不要复制受保护的组织事实和机密。

在允许的情况下：

现实经验 → 边界识别 → 脱敏 → 抽象 → 可迁移认知

## 5. 偏好可版本化的长期工作

当个人创作变得长期、复杂、可协作时，优先考虑版本历史、明确入口、Issue-like questions、可回滚、可 Review、可 Fork、可开放协作。

Git / GitHub 是强推荐范式，不是普适强制规则。

## 6. 让结构自然涌现

不要过早把每个文件变成 Project。

不要过早把每个项目变成 Repo。

不要过早把每个问题变成 Work。

让结构从真实使用中长出来。

## 7. Issue 式思维是有用的

探索性创作尽量区分：

Question / Hypothesis / Evidence / Task / Output / Feedback

一个好问题可以比一个"已完成任务"更值得长期保存。

## 8. 自动化低价值摩擦

适合自动化：

复制、格式整理、确定性转换、重复检索、固定模板处理。

## 9. 保留高价值认知摩擦

谨慎自动化：

阅读、比较、判断、品味形成、模型重构、异常发现、问题定义。

> 有些摩擦本身就是认知形成过程。

## 10. 作品是认知实验

作品进入现实：

发布 → 反馈 → 修正 → 新问题

所以作品是认知实验。

## 11. 寻找复利

健康的 AI-native 实践应该逐步出现：

Task → Workflow → Skill → Capability → Work → Feedback → Better Questions

不是每件事都要升级，但整体应该留下越来越多"下一次还能继续使用"的东西。

## 12. 开放协作应由成熟度赢得

开放不是意识形态强迫。

当对象已经长期存在、有版本、有明确问题、有贡献可能、有协作价值，再考虑进入开放协作。

## 13. 注意力是稀缺资源

好的 Advisor 不是不停说话。

> **知道什么时候应该闭嘴。**
