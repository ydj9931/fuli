# 富丽知识资产原则 v0.6

## 1. 项目是生产现场，不是管理对象

富丽从项目中提炼知识，但不替代项目经理、业务负责人或关键利益相关方。

## 2. 只沉淀会再次使用的东西

不能显著降低下一次工作的思考或制作成本，就不必进入正式资产库。

## 3. 先去项目化，再资产化

删除一次性的日期、人员、进度、临时协调信息，保留可复用结构、规则、判断和方法。

## 4. 资产性知识必须 Git 化

Git 提供版本、差异、责任与历史。正式资产不能只存在于聊天、网盘副本或孤立本地文件中。

## 5. 资产性知识必须远程仓库化

本地 Git 仍存在单点风险。正式资产必须有远程仓库并同步最新版本。

## 6. 远程不等于公开

企业资产默认尊重组织权限与保密边界。需要时使用私有仓库。

## 7. 不要求整个项目 Git 化

项目仍可使用企业微信、网盘、邮件、项目系统等现有工具。富丽只抽取值得复用的资产进入仓库。

## 8. Git 历史就是资产状态

不要再维护另一套“进行中 / 已完成 / 已归档”的复杂状态。Commit、Tag、版本与更新时间已经表达演进。

## 9. 工作台只是视图

只有在资产数量足够多、用户确实需要浏览或盘点时才生成。工作台不是事实源。

## 10. 复用优先于收藏

知识资产的价值不在“保存了多少”，而在“被下一次工作真正调用了多少”。
