# 富丽（Fuli）

> **让今天的工作，成为明天可复用的资产。**

富丽是一套运行在你已有超级 Agent 之上的**知识资产复利 Skill**。

她不替代 Codex、Claude Code、WorkBuddy 等 Agent，也不替代项目管理工具，更不要求你维护一个复杂的工作台或“第二大脑”。

富丽只做一件事：

> **从真实工作中识别、提炼并维护能够跨项目复用的知识资产。**

项目是知识资产的生产现场，不是富丽的管理对象。

因此，富丽默认不处理：项目进度、任务分工、催办、排期、关键利益相关方协调、会议跟进等传统项目管理事务。她只读取完成当前知识提炼所必需的上下文。

---

## 什么算知识资产

富丽重点关注：

- 模板
- 手册
- SOP / 标准流程
- 检查表
- 方法与决策框架
- 标准问题集
- 案例
- 可复用 Workflow / Skill
- 可长期维护的研究、课程与知识文档

判断标准不是“这次有没有用”，而是：

> **下一次类似工作，能不能直接复用，并减少重新思考和重新制作。**

---

## 正式资产的硬门槛

富丽把工作内容分为两类：

1. **工作材料 / 资产候选**：临时文件、过程稿、会议信息、一次性项目材料。
2. **正式知识资产**：已经完成抽象、去项目化，并进入长期版本管理的内容。

一份内容只有同时满足以下条件，才被富丽视为正式知识资产：

1. 有明确的跨项目复用价值；
2. 已去除不必要的项目特定信息；
3. 权属、保密和使用边界清晰；
4. **进入 Git 版本管理；**
5. **已连接并同步到远程仓库。**

> **没有 Git + 远程仓库，就只有资产候选，没有正式知识资产。**

这不意味着所有项目文件都必须 Git 化。项目可以继续存在于企业微信、网盘、邮件或本地目录；只有被提炼出的资产性知识，必须进入资产仓库。

企业工作中提炼出的资产默认遵守组织的保密、产权和访问规则。远程仓库可以是私有仓库，远程化不等于公开化。

---

## 使用方式

```text
富丽提炼
```

从当前工作中找出真正值得跨项目复用的内容，优先给出少量高价值资产候选。

```text
富丽资产化
```

把选中的候选整理为模板、手册、SOP、检查表、案例、方法或 Workflow，并进入 Git + 远程仓库管理。

```text
富丽评审
```

检查已有知识资产是否仍然可复用、是否出现重复、是否应该合并或升级。

```text
富丽升级
```

检查并更新富丽 Skill 本身。

`富丽扫描` 保留为兼容入口，默认等价于“检查当前工作中有什么值得提炼为知识资产”。

---

## 工作台不是核心

富丽默认不维护固定工作台。

只有当用户需要跨大量资产浏览、阶段盘点或集中整理时，才临时生成视图。视图不是事实源，仓库中的文件和 Git 历史才是。

> **Git 历史就是资产历史。不要再为知识资产额外维护一套状态。**

## 安装

推荐全局安装到 Agent Skills 目录：

```bash
# Claude Code
git clone https://github.com/ydj9931/fuli.git ~/.claude/skills/fuli

# 其他 Agent
git clone https://github.com/ydj9931/fuli.git <Agent 全局 Skills 目录>/fuli
```

> 富丽安装到 Agent，而不是安装到项目。一次安装，所有项目可用。

---

## 更新

```bash
# 在 Agent 中
富丽升级

# 或手动更新
cd <富丽安装目录> && git pull
```

---

## 一句话

> **富丽不管理你的项目，她负责让项目中真正有价值的知识，不再随着项目结束而消失。**
