# Part 0｜前置理论背景（上下文重建，非逐字原文）

本项目在进入产品收敛前，经历了如下关键理论演化：

- 从“知识创造系统”转向“认知系统 / Cognitive System”。
- 区分 Information、Knowledge、Capability、Action、Outcome。
- 讨论知识原子：概念、关系、模式、规则、行动等。
- 讨论 Nonaka/SECI 及“经验 → 案例 → 模式 → 模型 → 规则 → Skill → 行动 → 新经验”。
- 明确：知识不是最终价值，而是认知与能力循环中的中间态。
- 明确：类比不是创新的最底层机制；TRIZ/Altshuller 的矛盾识别与创新算子更接近底层变换机制。
- 将市场从“下游验证”前置为“上游传感器”：异常、冲突、矛盾、未满足需求是认知创造入口。
- 将 GitHub / 开源社区理解为一种分布式问题解决、贡献、Review、验证、反馈和共同记忆机制。
- 从个人认知系统进一步讨论组织认知、认知网络、认知生态。
- 经第三方严厉评审后收敛：不再试图先解释整个“认知文明”，而回到一个真实产品——面向 AI 时代重构个人工作与创作方式。

# AI 时代个人工作与创作操作系统

（AI-native Cognitive Work System）

真正的突破方向应当从 Task AI 转向 Cognitive Work System：

现实 → 观察 → 发现问题 → 形成理解 → 产生方案 → 创造作品 → 获得反馈 → 更新认知。

个人应当成为第一服务对象；系统最终由 Reality Interface、Thinking Space、Cognitive Memory、Creation Engine、Feedback Network 等层逐步长出来。

开放性不应从“大平台”开始，而应遵循 Personal First, Network Later。

## Assistant

Advisor 的对象不能只理解为“扫描文件”，而应该持续感知完整的工作—创作—协作环境。

三个核心维度：

- Object：对象是什么；
- Space：它存在于哪个环境；
- Activity：人和 AI 对它做了什么。

建议把环境分为：
1. Personal Space：本地文件、Markdown、PDF、Office、素材等；
2. Collaboration Space：GitHub Repository / Issue / PR / Commit / Release 等；
3. Publication Space：微信公众号、知乎、网站等发布与反馈渠道；
4. Organization Space：企业微信文档、微盘、智能表格、聊天、日历、会议、邮件等；

底层对象因此应该从 File / Document / Task 升级到 Activity Event，例如：
created_file、edited_document、opened_issue、had_meeting、sent_email、asked_ai、accepted_ai_suggestion、published_work 等。

产品原则：

> **Connect, don't centralize. Understand, don't merely collect.**
