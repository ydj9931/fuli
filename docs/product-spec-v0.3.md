# 富丽（Fuli）v0.3 产品方案书

版本：v0.3  
日期：2026-08-11  
状态：产品收敛 / 可执行

---

# 1. 一句话定位

> **富丽是一位运行在超级 Agent 之上的 AI 工作与创作顾问，帮助用户发现工作中值得复利的东西，并以最低行动成本把它们留下来。**

富丽不替代模型，不替代 Codex、Claude Code、WorkBuddy 等超级 Agent，也不重新制造一个 Agent。

> **Agent 有能力，富丽给它判断标准。**

---

# 2. v0.3 的核心问题

v0.1 验证：Skill 可以运行。  
v0.2 明确：富丽不是文件扫描器，而是判断层。  
v0.3 要验证：

> **同一个超级 Agent，加载富丽之后，是否能更早、更准确、更克制地发现用户工作中真正值得复利的东西？**

本版本主题：

> **证明判断增益。**

---

# 3. 目标用户

当前主要面向中文用户。

核心用户是已经长期使用强模型 / 超级 Agent，同时拥有真实工作与长期个人创作诉求的人。

首次出现可使用：**富丽（Fuli）**。后续产品文案统一使用：**富丽**。

国际化暂不作为 v0.3 目标。

---

# 4. 用户价值

多数 AI 使用容易形成：

```text
Task → AI 执行 → 节省时间 → 下一个 Task
```

富丽关注的是：

```text
真实工作 → 发现问题 → 形成可复用方法 → 形成能力 / 项目 / 作品
→ 获得真实反馈 → 形成更好的认知 → 发现更好的问题
```

富丽的核心评价函数不是“完成更多”，而是：

> **今天的工作，有多少能在未来继续产生价值？**

---

# 5. v0.3 四个核心目标

## 5.1 判断增益

富丽必须证明：

> 同一个 Agent + 富丽，应该比裸 Agent 做出更高质量的工作与创作判断。

重点比较：真正重要的问题、重复模式、可复用机会、潜在作品与研究问题、无意义建议减少、避免过度自动化、Aha。

## 5.2 更快产生 Aha

第一次使用的目标不是全面检查，而是尽快让用户感受到：

> **“原来的 Agent 不会这样看我的工作。”**

理想首次输出：

```text
事实 → 模式 → 值得记住的信号
```

Aha 不是“AI 说了一句很聪明的话”，而是：

> **把用户原本视为零散事件的东西，升格为一个新的工作对象、模式或问题。**

## 5.3 最小行动

> **发现价值，不等于制造任务。**

默认先问：

> **为了不让这个价值消失，现在最小需要做什么？**

优先级：

```text
Ignore → Watch → Capture → Small Action → Invest
```

绝大多数早期信号应停留在 Watch / Capture。

富丽应该经常允许：

> **“现在什么都不用做，我先替你记着。”**

## 5.4 可解释、可修正的渐进式个性化

富丽首先遵循公开可读、可修改、可共创的 **默认复利创作规范**，随后在真实工作中逐渐学习用户个人创作偏好。

优先级：

```text
安全 / 权限边界
↓
用户明确指令
↓
个人已确认创作偏好
↓
当前情境
↓
默认复利创作规范
```

个人偏好优先于默认方法论。

---

# 6. 默认复利创作规范

v0.3 首版只保留 8 条：

1. **发现价值，不等于制造任务。**
2. **默认采取最小足够行动。**
3. **先保存可能性，再决定是否投入。**
4. **自动化低价值摩擦，保留高价值认知摩擦。**
5. **没有足够证据时，观察优于结论。**
6. **优先让今天的工作留下未来还能使用的东西。**
7. **重要建议必须解释证据与判断依据。**
8. **用户的创作习惯优先于富丽的默认偏好。**

这套规范是公共资产，可以通过开源方式共同讨论、修改和演进。

> **经验归用户，模式可共创。**

---

# 7. 渐进式个性化

富丽不要求新用户填写创作问卷。

首次使用后，用户工作空间默认存在：

```text
.fuli/
├── preferences.md
└── state.md
```

`preferences.md` 默认创建，不需要用户手工新建。刚开始可以为空。

区分：
- 已确认偏好；
- 待确认偏好。

只有用户明确确认后，才把推测升级为长期个人偏好。

`state.md` 只保存富丽理解当前工作空间所需的最小状态，不建立新的知识库，不复制大量原始工作内容。

---

# 8. 富丽的最小工作闭环

v0.3：

> **观察 → 判断 → 最小捕获 → 持续观察 → 再判断**

不默认进入 Create / Publish / New Project。

在未来连通创作记录、发布渠道、作品反馈、长期历史之后，富丽才更有资格主动提出高成本创作建议。

---

# 9. 三个核心操作

## SCAN

> **现在最值得注意的是什么？**

首次运行优先返回：一个确定问题、一个工作模式、一个值得记住的信号（有证据时）。

## REVIEW

> **和上次相比，什么正在变化？**

重点：重复、停滞、新证据、模式强化、过去建议结果、个人偏好变化。

### Compressed Review

第一次使用时不要求用户安装 Git。

优先利用现有历史痕迹：文件修改时间、文件名 / 版本、文档日期、已有 Git 历史（如果本来就有）、宿主 Agent 可访问历史。

> **历史优先利用，不要求用户为了富丽制造历史。**

Git 是增强项，不是门票。

## REFLECT

> **这些变化背后，有什么值得长期关注？**

必须有证据、标明不确定性、给最小行动，不把洞察自动升级成创作任务。

---

# 10. 判断层级

```text
L0  硬发现
L1  工作空间卫生
L2  结构问题
L3  AI 就绪度
L4  Workflow / Skill 信号
L5  Project / Work / 创作信号
L6  认知 / 研究信号
```

层级越高，证据要求越高，自动执行权限越低，越需要克制。

---

# 11. 建议类型

- `HARD_FINDING`
- `BEST_PRACTICE`
- `CREATOR_PRINCIPLE`
- `INSIGHT_HYPOTHESIS`

每条重要建议尽量说明：Evidence、Why it matters、Recommendation、Basis、Confidence、Minimum action。

---

# 12. 第一次用户体验

第一次使用：

1. 不要求填写用户画像；
2. 不要求先安装 Git；
3. 不自动重构工作空间；
4. 自动初始化最小 `.fuli/`；
5. 告知用户默认复利创作规范可浏览和修改；
6. 输出尽量少；
7. 优先制造判断差异，而不是建议数量。

推荐输出：

```text
富丽第一次观察

我确认的一件事
……

我注意到的一个模式
……

今天值得记住的一件事
……
```

最后只给轻动作：记下 / 忽略 / 展开证据。

如高阶证据不足：

> **“目前没有足够证据形成更高阶判断，我先观察。”**

---

# 13. Aha 原则

早期核心指标可以使用 **Aha Rate**，重点关注：
- “我之前没意识到”；
- “改变了我的下一步行动”。

但不能为了 Aha 制造高阶推断。

> **真正的 Aha 来自认知升格，而不是人工惊喜。**

---

# 14. 裸 Agent 对比评测

核心评测：**Agent Baseline vs Agent + 富丽**。

保持同一个模型、同一个 Agent、同一个工作空间、同一个用户问题、同样的可访问证据。

评价：
1. Problem Detection Lift
2. Pattern Detection Lift
3. Object Formation Lift
4. Aha Lift
5. Restraint / Burden Reduction
6. Explainability

关键问题：

> **哪一个回答让用户更清楚“什么值得留下，而不是什么都值得做”？**

---

# 15. Demo Case

v0.3 不建设 Playground 产品。

只保留一个极小 `demo-case`，用于快速解释富丽与裸 Agent 的差异和基础回归测试。

它是合成测试资产，不是真实用户案例库。

---

# 16. 隐私与资产边界

> **富丽从用户经验中工作，但不把用户经验变成公共资产。**

公共项目共享：方法、抽象模式、默认复利创作规范、合成测试案例。

不默认共享：用户真实文件、用户创作记录、用户工作轨迹、用户私有反馈、用户个人偏好。

---

# 17. Native First

富丽不重复超级 Agent 已有能力。

优先使用宿主 Agent 的文件读取、搜索、Git、内容分析、当前任务上下文、可访问历史。

内置脚本只负责确定性补充，例如文件元数据、Hash 重复检测、Snapshot、时间比较。

> **Native first, script when useful.**

---

# 18. 当前非目标

v0.3 不做：独立 App、新聊天 UI、Workbench、企业微信连接器、发布渠道连接器、复杂知识图谱、新 Agent Runtime、Preference Engine、用户画像系统、大型 Playground、公开真实用户案例库。

---

# 19. v0.3 成功标准

> **富丽开始持续产生相对裸 Agent 可验证的判断增益，同时保持低负担、可解释和可修正。**

产品关键词：

> **判断增益 · 最小行动 · Aha Moment · 渐进式个性化**

---

# 20. 长期方向

```text
富丽 Advisor
→ 长期真实使用
→ 更准确的个人创作偏好
→ 创作记录
→ 发布渠道
→ 作品反馈闭环
→ 更可靠的创作投入判断
```

未来 Workbench 和 Cognitive Partner 应从真实使用中长出来，而不是提前建设。

> **先证明富丽的判断，再给她更多身体。**
