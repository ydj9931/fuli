# 富丽 v0.6 产品说明

## 版本主题

> **从“复利创作顾问”进一步收敛为“知识资产复利助手”。**

## 核心定位

富丽运行在已有超级 Agent 之上，从真实工作中识别、提炼和维护能够跨项目复用的知识资产。

一句话：

> **项目是知识资产的生产现场，不是富丽的管理对象。**

## 为什么收缩

企业项目中最关键的信息往往来自关键利益相关方、隐含约束、组织关系和临时变化。这些内容高度依赖现场语境。

如果富丽试图同时管理项目进度、任务分工、需求变化和利益相关方沟通，会导致：

- 上下文快速膨胀；
- 项目状态与真实意图脱节；
- 短期信息稀释长期价值；
- 形成第二套需要人工维护的项目系统；
- AI 判断质量反而下降。

因此 v0.6 不再追求“更懂整个项目”，而追求“更准确地留下项目中值得复用的部分”。

## 产品边界

| 富丽重点负责 | 富丽默认不负责 |
|---|---|
| 模板、手册、SOP | 进度跟踪 |
| 检查表、标准问题集 | 任务分工 |
| 方法、决策框架 | 催办、排期 |
| 案例、课程、研究资产 | 利益相关方协调 |
| Workflow / Skill | 会议管理 |
| Git 版本与远程资产仓库 | 固定工作台 |

## 两个世界

```text
工作世界
企业微信 / 邮件 / 网盘 / 本地 / 项目系统 / 会议
      ↓ 富丽识别与提炼
资产世界
Git 仓库 + 远程仓库
```

富丽不要求所有项目资料迁入 Git。

**只有被认定为资产性知识的内容必须 Git + 远程仓库化。**

## 正式资产门槛

正式资产 = 可复用 + 去项目化 + 边界清晰 + Git Tracked + Remote Synced。

缺少 Git 或远程仓库时，只能称为资产候选。

## 工作台定位

工作台从产品核心降级为“按需生成的临时观察视图”。

- 不默认存在；
- 不要求每日打开；
- 不保存另一套项目状态；
- 只有资产规模较大、需要盘点或可视化时才生成。

事实源始终是仓库文件与 Git 历史。

## 状态原则

> **知识资产没有额外状态系统，只有文件和历史。**

创建时间、Commit、Tag、版本、贡献者、变更记录已经足够表达资产演进。

v0.6 不再自动维护项目级 `.fuli/state.md`。

## 用户入口

核心动作：

1. `富丽提炼`：发现值得复用的资产候选；
2. `富丽资产化`：去项目化并进入 Git + Remote；
3. `富丽评审`：检查复用质量、重复与版本演进；
4. `富丽升级`：更新 Skill 本身。

`富丽扫描` 作为兼容入口保留。

## 企业资产原则

企业项目形成的知识资产默认遵守组织权属、保密和访问控制。

- 远程仓库不等于公开仓库；
- 未明确允许公开时，默认优先私有远程仓库；
- 不复制客户、合作方或组织的受限原始材料；
- 优先提炼结构、方法、模板与决策逻辑。

## 关键成功指标

不再以“管理多少项目/任务”为核心指标。

优先观察：

- 资产二次使用率；
- 跨项目复用次数；
- 模板/手册/SOP 的迭代次数；
- 因复用减少的重复制作；
- 资产仓库的持续版本演进；
- 是否形成稳定的个人或组织知识底座。

## 核心原则

> **不为了系统完整而制造界面，不为了知识管理而复制工作。**

> **只有真正值得未来再次使用的内容，才进入资产世界。**
